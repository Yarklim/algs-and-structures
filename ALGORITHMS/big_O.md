## Сложность по времени (Time Complexity)

### O(1) — Константная сложность

* **Что означает:** Время выполнения не зависит от размера входных данных. Алгоритм делает фиксированное количество операций всегда.
* **Примеры:**
* Доступ к элементу массива по индексу (a[i]).
* Вставка или удаление из хэш-таблицы (в среднем).
* Push/Pop операции в стеке на базе массива.

---

### O(log log n) — Двойная логарифмическая

* **Что означает:** Чрезвычайно быстрый рост, практически неотличимый от константы на реальных данных.
* **Примеры:**
* Интерполирующий поиск (в среднем для равномерно распределенных данных).
* Поиск, вставка и удаление в дереве ван Эмде Боаса (van Emde Boas tree).

---

### O(log n) — Логарифмическая

* **Что означает:** При увеличении входных данных в 2 раза количество операций увеличивается всего на 1 шаг. Возникает при делении задачи пополам на каждом шаге.
* **Примеры:**
* Бинарный (двоичный) поиск в отсортированном массиве.
* Поиск, вставка и удаление в сбалансированных бинарных деревьях поиска (AVL, Красно-черное дерево).
* Возведение в степень методом бинарного возведения.

---

### O(√n) — Квадратно-корневая

* **Что означает:** Количество операций пропорционально квадратному корню из объема данных.
* **Примеры:**
* Простейшая проверка числа на простоту (перебор делителей до √n).
* Алгоритм Мо (Mo's Algorithm) для обработки запросов на отрезках.
* SQRT-декомпозиция массива.

---

### O(n) — Линейная

* **Что означает:** Время работы растет строго пропорционально размеру данных: в 2 раза больше элементов — в 2 раза больше времени.
* **Примеры:**
* Линейный поиск элемента в неотсортированном массиве.
* Поиск минимума / максимума / суммы в массиве.
* Подсчет длины связного списка.

---

### O(n log n) — Линейно-логарифмическая (Квазилинейная)

* **Что означает:** Немного медленнее линейной. Обычно возникает при разбиении задачи на log n уровней, где на каждом уровне обрабатывается n элементов.
* **Примеры:**
* Эффективные алгоритмы сортировки: **MergeSort**, **HeapSort**, **QuickSort** (в среднем).
* Быстрое преобразование Фурье (FFT).

---

### O(n^2) — Квадратичная

* **Что означает:** Время работы растет пропорционально квадрату размера данных. Обычно результат использования двух вложенных циклов по n.
* **Примеры:**
* Простые алгоритмы сортировки: **BubbleSort**, **SelectionSort**, **InsertionSort**.
* Проверка всех пар элементов в массиве.

---

### O(n^3) — Кубическая

* **Что означает:** Результат использования трех вложенных циклов. Становится неприменимой на практике уже при n > 1000.
* **Примеры:**
* Наивное перемножение двух матриц размера n times n.
* Алгоритм Флойда — Уоршелла (поиск кратчайших путей между всеми парами вершин графа).

---

### O(2^n) — Экспоненциальная

* **Что означает:** Каждое добавление одного элемента на вход удваивает время выполнения. Неприменимо для n > 30-40.
* **Примеры:**
* Наивный рекурсивный поиск n-го числа Фибоначчи.
* Точное решение задачи о ранце (Knapsack) методом полного перебора.
* Генерация всех подмножеств множества из n элементов.

---

### O(n!) — Факториальная

* **Что означает:** Самый быстрый практический рост сложности. Становится невычислимой уже при n > 12-15.
* **Примеры:**
* Полный перебор для решения задачи коммивояжера (TSP).
* Генерация всех перестановок массива из n элементов.

## Асимптотическое упрощение / Асимптотический анализ

* O(n + n^2)			=>	O(n^2)
* O(n^2/2)				=>	O(n^2)
* O(n + log n)			=>	O(n)
* O(60*2^n + 10*n^100)	=>	O(2^n)
* O(n^2 + m)			=>	O(n^2 + m) - нельзя откинуть m, т.к. его значение неизвестно

## Сложность встроенных нативных методов

* Нативные методы (.filter(), .indexOf(), .slice(), .sort() и др.) имеют собственную асимптотическую сложность, которая обязана учитываться в общем анализе алгоритма.
* Применение таких методов внутри циклов умножает их сложность (например, .indexOf() внутри цикла по n дает O(n^2)).

- .length, .pop(), .push()								O(1)			Выполняются за константное время
- .indexOf(), .includes(), .find(), .filter(), .map()	O(n)			Линейный проход по массиву
- .shift(), .unshift(), .splice()						O(n)			Требуют сдвига индексов всех последующих элементов
- .sort()												O(n log n)		Используют быстрые алгоритмы сортировки (TimSort в V8)

## Сложность по памяти (Space Complexity)

* **Дополнительная память (Auxiliary Space):** Учитывается только **новая** память, выделяемая алгоритмом в процессе работы (переменные, массивы, стек рекурсии), без учета входных данных.
* **Принцип оценки:** Аллокация структур данных увеличивает сложность (массив на n элементов — O(n), матрица n times n — O(n^2)), а вызов рекурсивных функций расходует память на стек вызовов пропорционально максимальной глубине рекурсии.

### Шпоргалка по сложностям

| Сложность | 				Что означаeт 					| 											Примеры 										

| O(1) 		| Память фиксирована и не зависит от размера n. | Примитивные переменные, счетчики, циклические указатели, inplace-сортировки (HeapSort). 	

| O(log n) 	| Память растет логарифмически от n. 			| Стек рекурсии при сбалансированном делении задачи (QuickSort, бинарный поиск через рекурсию).

| O(n) 		| Память растет строго пропорционально n. 		| Создание нового массива/списка на n элементов, хэш-таблица (Set/Map), стек рекурсии при 	    глубине n (глубокий рекурсивный обход).

| O(n^2) 	| Память растет квадратично от n. 				| Создание двумерного массива / двумерной матрицы n times n, графа в виде матрицы смежности.
